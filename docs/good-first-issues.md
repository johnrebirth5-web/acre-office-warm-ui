# Good First Issues

This page lists approachable contribution ideas for new contributors. Please open or comment on an issue before starting larger changes so maintainers can confirm scope.

## Documentation

- Improve local setup notes for macOS, Linux, or Windows contributors.
- Add screenshots or short walkthroughs for the Office Console and Listing Studio.
- Clarify Chrome extension development and package-loading steps.
- Expand environment variable explanations with safe local examples.
- Review docs for outdated internal wording and propose clearer public language.

## Testing

- Add focused tests for small route handlers that already have clear behavior.
- Add regression tests for permission edge cases.
- Improve tests around transaction filtering, contact linking, or listing share flows.
- Add extension build checks for manifest or content-script assumptions.

## UI Consistency

- Replace page-local button, table, or empty-state patterns with existing shared `@acre/ui` primitives.
- Improve accessible labels and keyboard behavior in focused controls.
- Clean up small layout inconsistencies without redesigning whole modules.

## Developer Experience

- Improve script documentation in the README.
- Add troubleshooting notes for common local database setup issues.
- Make error messages clearer in local-only setup paths.
- Add examples for safe placeholder configuration.

## Issue Labels to Look For

Suggested labels for maintainers to use:

- `good first issue`
- `documentation`
- `tests`
- `developer experience`
- `ui consistency`
- `help wanted`
